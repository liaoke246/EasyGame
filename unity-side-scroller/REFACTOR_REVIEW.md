# Dead Rails 0.4.0 制作审查

## 当前判断

这是具备角色选择、基础移动、近战、怪物、PVP 和复活的联机可玩原型。主要问题来自物理规则、表现状态和发布验证之间缺少共同约束。现阶段应优先让已有操作稳定、关卡可达、受击反馈可信，再增加装备、任务和更多内容。

本轮保持游戏大厅和已有俯视角游戏的入口，集中重构独立的 Unity 横版项目。

## 本轮修正

| 原问题 | 原因 | 现在的约束 |
| --- | --- | --- |
| 接地、跳跃不可靠 | 重叠检测把墙体、平台内部、其他角色当作地面；离线和联机各有一套跳跃逻辑 | 共用固定步长运动器；检查支撑面法线；保留跳跃缓冲、离地宽限和零摩擦贴墙下落 |
| 后半段台阶跳不上去 | 数处高度与间距超出实际跳跃轨迹 | 增加中间踏步；从生成的真实碰撞体读取路线，验证全部相邻平台双向短跳与长跳 |
| 尸体遁地、复活滑动 | 关闭碰撞后重力仍生效；复活残留旧插值数据 | 死亡关闭物理模拟；复活恢复状态并清空网络插值历史 |
| 僵尸边缘来回转身 | 每个物理帧反转方向；巡逻读取插值后的显示位置 | 越界固定朝内；窄平台等待；物理规则读取刚体位置 |
| 动作与移动不一致 | 客户端不模拟物理，却用刚体速度驱动动画 | 同步动作与移动速度；动作循环连续推进；攻击事件携带固定朝向 |
| 命中形状和攻击时机奇怪 | 玩家史莱姆保留人形碰撞体；攻击没有完整起手/恢复约束 | 碰撞体匹配角色高度并共用脚底坐标；起手后结算命中，受击/死亡取消待结算攻击 |
| 重复伤害、穿墙打人 | 未去重的范围查询 | 每次攻击同一刚体只结算一次，静态地形阻挡攻击 |
| 血条位置/经验异常 | HUD 缩放污染其他绘制；经验显示与等级不一致 | 绘制后恢复 GUI 状态；经验实际升级并保留溢出 |
| 手机连点、切后台继续移动 | 两套输入渠道与未消费的点击边沿 | 单一输入桥接、多指归属、失焦清零；服务端过期输入自动释放 |
| 一直连接或加载没有反馈 | 缺少失败、超时和重试状态 | 显示加载失败；连接/同步超时、退避重连和手动重试 |
| 修改后网页仍是旧行为 | 预编译文件未证明与源码一致 | 双端构建清单记录源码指纹和产物哈希，发布前拒绝旧包或被修改的包 |

## 已执行的自动验证

- Unity 独立物理场景中运行 13 组移动场景，包含每种跳跃各 32 条有向平台连接，以及出口返回路线。
- 5 组战斗查询场景；三种玩家角色的 21 个动作状态检查。
- 实际 Mirror 无监听服务器创建玩家、僵尸和史莱姆，验证死亡、2.4 秒物理模拟中尸体不下沉、复活、插值清零、无效伤害和巡逻边缘。
- 输入数值、乱序、过期、序号溢出、名字、角色、视口与升级规则。
- 网页脚本 7 组行为测试；构建校验器 10 组包含篡改、缺失、版本不一致的测试。

2026-09-06 本地构建验收：WebGL 与 Linux 专用服务器均成功构建，双端源码指纹及全部文件哈希匹配。浏览器中两名玩家（女游侠、蓝史莱姆）同时连接本地 Unity 服务端；移动同步、近战四次将血量从 100 依次降至 75/50/25/0、击杀/死亡计数、满血复活均通过。女角色可从地面跳上第一平台。844×390 横屏操作按钮完整显示且能触发跳跃/攻击；服务器重启后两端自动重连成功。

原游戏的 Node 构建、动作与战斗检查，以及双玩家联机冒烟测试通过；游戏大厅两条入口已重新组装验证。自动测试和桌面浏览器尺寸测试覆盖明确场景，不代表所有真实手机与网络状况都已验证。

## 产品上仍未完成的部分

- 移动采用服务器权威与插值，高延迟网络仍有操作延迟；尚未加入客户端预测与服务器校正。
- 三种角色有各自轮廓，但没有完成竞技数值平衡。PVP 目前适合体验和测试。
- 经验等级是基础系统；装备成长、任务、持久化存档和断线恢复角色进度尚未完成。
- 地图已验证可达，尚缺完整的探索目标、战斗节奏、精英怪和关卡完成条件。
- 手机网页输入已有行为验证；真实 iOS Safari 的渲染性能、发热与长时运行仍需设备验收。
